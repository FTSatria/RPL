B. Dimensi Profil Lulusan (DPL)

DPL1

Penalaran Kritis

Menganalisis kebutuhan fungsional dan non-fungsional sistem dari klien nyata serta memetakan alur logika bisnis ke dalam diagram visual terstruktur.

DPL2

Kolaborasi dan Komunikasi

Bekerja sama dalam tim pengembang perangkat lunak, membagi peran analis sistem, dan mempresentasikan spesifikasi teknis kepada pemangku kepentingan.

DPL3

Kemandirian dan Kreativitas

Merancang solusi arsitektur berorientasi objek yang inovatif dan terukur dengan memanfaatkan asistensi teknologi kecerdasan buatan (AI) secara etis.

Tujuan Pembelajaran

Pilih unsur ABCD untuk melihat bagian kalimat yang dimaksud.

Melalui model Problem Based Learning terintegrasi Teaching Factory, peserta didik kelas XI Konsentrasi Keahlian Rekayasa Perangkat Lunak mampu menganalisis kebutuhan klien serta merancang dokumen Software Requirements Specification (SRS) dan diagram pemodelan berorientasi objek (Use Case, Activity, dan Class Diagram) secara komprehensif, logis, dan tepat sesuai standar industri rekayasa perangkat lunak.

Desain Pembelajaran

Praktik pedagogis, lingkungan, kemitraan, dan pemanfaatan digital.

Praktik Pedagogis

Model Problem Based Learning (PBL) berorientasi Teaching Factory (TeFa), dengan murid berperan sebagai profesional Junior System Analyst. Pembelajaran menerapkan deep learning (Mindful, Meaningful, Joyful Learning) dengan mengombinasikan visual scaffolding, simulasi wawancara klien, perancangan diagram interaktif, dan validasi sejawat.

Lingkungan Pembelajaran

Laboratorium Komputer SMKN 3 Palu disimulasikan sebagai Software House / Studio Digital Agency. Meja ditata berbentuk klaster tim kerja (scrum teams) dengan akses internet stabil 50 Mbps untuk eksplorasi referensi, repository Google Classroom, dan peranti pemodelan digital.

Kemitraan Pembelajaran

Kolaborasi dengan Unit Produksi / Teaching Factory SMKN 3 Palu (misalnya Unit Jasa Percetakan atau Kantin Digital) dan UMKM mitra lokal di Kota Palu sebagai penyedia studi kasus nyata (klien autentik) yang membutuhkan sistem informasi berbasis web/mobile.

Pemanfaatan Digital

  • Google Classroom untuk tugas, lembar kerja, dan materi.
  • Quizizz untuk asesmen formatif interaktif visual.
  • Generative AI (ChatGPT/Claude/Gemini) sebagai mitra brainstorming skenario use case.
  • Aplikasi diagramming: PlantUML, Draw.io, atau StarUML.

Peran Junior System Analyst dalam Rekayasa Perangkat Lunak

System Analyst menjadi jembatan antara kebutuhan bisnis klien (problem domain) dan solusi teknologi yang dibangun programmer (solution domain).

Tugas utama

  • Elisitasi kebutuhan (fact-finding).
  • Menganalisis kelayakan.
  • Menuangkan hasilnya ke dalam Software Requirements Specification (SRS).

Pemodelan Kebutuhan Fungsional dengan Use Case Diagram

Use Case Diagram memodelkan interaksi antara aktor eksternal (pengguna atau sistem lain) dengan fungsionalitas sistem.

Pilih jenis relasi untuk menyorot bagian diagram.

AktorEntitas luar yang berinteraksi dengan sistem (Kasir, Pelanggan, Manajer Gudang).
Use CaseFungsionalitas tingkat tinggi sistem (‘Mengelola Data Barang’, ‘Melakukan Transaksi Penjualan’).
«include»Use case wajib memanggil use case lain untuk menyelesaikan prosesnya. Contoh: ‘Checkout’ include ‘Validasi Pembayaran’.
«extend»Perilaku opsional atau kondisional. Contoh: ‘Cetak Invoice Fisik’ extend ‘Transaksi Berhasil’ jika pelanggan meminta struk.

Pemodelan Alur Logika Bisnis dengan Activity Diagram

Activity diagram memodelkan alur kerja (workflow) langkah demi langkah dari suatu proses bisnis. Contoh di bawah adalah alur transaksi kasir yang dipisah per penanggung jawab.

Fitur kunci

Pemodelan Struktur Sistem Menggunakan Class Diagram

Class Diagram adalah diagram struktural inti dalam OOP yang menggambarkan struktur statis sistem. Setiap kelas memuat nama kelas, atribut, dan method/operasi.

+public-private#protected

Relasi antarkelas

Dari diagram ke kerangka kode

Contoh kerangka kelas TypeScript dari class diagram sistem kasir TeFa (ilustrasi).

class User {
  protected nama: string;
  private kataSandi: string;
  masuk(): boolean { /* ... */ }
}

class Kasir extends User {            // Generalization
  inputTransaksi(): Transaksi { /* ... */ }
}

class Transaksi {
  private total: number;
  private items: DetailTransaksi[];   // Composition 1..*
  hitungTotal(): number { /* ... */ }
}

class DetailTransaksi {
  private jumlah: number;
}

Simulasi

Latihan langsung untuk dua kegiatan inti: wawancara klien pada Pertemuan 1 dan uji coba mini code generator pada Pertemuan 2.

Skenario

Anda Lead Analyst sebuah tim Software House. Klien Anda adalah Manajer Unit TeFa Mart SMKN 3 Palu, yang masih memakai pencatatan kasir dan inventaris manual. Pilih pertanyaan satu per satu untuk menggali kebutuhan. Tidak semua pertanyaan efektif, jadi perhatikan jawaban dan catatan yang muncul.

Jawaban klien adalah skenario contoh untuk latihan, bukan data unit usaha yang sebenarnya.
